# R0015: static library

toy links only shared libraries. An `extern "name"` block or a `-l` flag named a
static archive (`.a`) or an object file (`.o`), or the library search found only
`lib<name>.a` and no shared library. The emitted binary loads each library at run
time, so there must be a shared library to load; copying archive code into the binary
(static linking) is not supported yet.

```
extern "libsqlite3.a" {   // error: library 'libsqlite3.a' is a static library;
    fn sqlite3_libversion_number() -> int32   // toy links only shared libraries
}
```

```
// toy build main.toy -L vendor   (vendor/ holds only libfoo.a)
extern "foo" { fn foo_init() }    // error: library 'foo' is only a static library
                                  // ('vendor/libfoo.a'); toy links only shared libraries
```

Its note names the target's shared library file (on macOS, `lib<name>.dylib`).

Fixes:

- Build or install the library as a shared library (on macOS,
  `cc -shared -o libfoo.dylib ...`) and name it, or the folder it is in with `-L`.
- Name the library without an extension (`extern "foo"`, `-l foo`) so the search looks
  for the shared library `libfoo`.
