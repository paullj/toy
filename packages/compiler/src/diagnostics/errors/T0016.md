# T0016: type arguments cannot be inferred here

A bare (no-explicit-args) generic call infers each type parameter from the
argument types. When a type parameter appears only in the return type (or in no
value parameter at all), the arguments carry no information to bind it; unless the
call's expected type binds it through the return type, it is left unbound and the call
is rejected.

```
fn ro[T]() -> T { loop {} }
fn main() -> int { ro() return 0 }   // nothing constrains T
```

Supply explicit type arguments so the parameter is pinned — `ro[int]()`. A method of a
generic type takes its own the same way: with `fn none[U](self) -> Option[U]` on
`impl Box[T]`, `b.none()` is this error and `b.none[int]()` pins `U` (the receiver
binds `T`). An associated fn called on the bare type (`Box.with[bool](1, true)`) has no
receiver to bind the impl's parameters, so write them on the type: `Box[int].with[bool](1, true)`.
So does one named as a value with no expected fn type to bind them: `f := Box.new` is this
error, while `f := Box[int].new` and `f: fn(int) -> Box[int] = Box.new` check. An
argument of a generic callee gives no expected type while the callee's own type
parameters are open, so `xs.map(Box.new)` is this error too: write `xs.map(Box[int].new)`.

A generic fn whose args leave a type parameter open takes it from the expected type
instead, as does an associated fn for a parameter of its type: `o: Option[int] =
nothing()` and `v: Vec[int] = Vec.new()` check, as do both returned from a fn declared
`-> Option[int]` / `-> Vec[int]` or passed to a parameter of that type. With no expected
type it is this error. A receiver's expected type is its outer call's, so
`nothing().is_some()` is this error too.

A builtin `.into()` or `.try_into()` on a number or `char` converts to the type its context
names. As a binary operand it takes the other operand's type (`n + x.into()`,
`c += x.into()`, `x.into() < n`); beside a literal, which has no type of its own, it takes
the operator's expected type. With neither, as in `y := x.into()` or `x.into() == 5`, the
target is unknown: give the result a type, `y: int = x.into()`.

An empty list literal `[]` is `Vec[T].new()` with nothing to fix `T`, so it needs a
type from its context: `xs: Vec[int] = []`.
