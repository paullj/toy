# R0016: library not found

An `extern "name"` block or a `-l name` flag names a library that the linker cannot
find. A plain name is looked up as the shared library `lib<name>` in each `-L` folder,
in order, then in `/usr/local/lib` and `/usr/lib`, then in the system library cache,
where a system keeps libraries that have no file on disk. A name that contains a `/`
or ends in the shared library extension is a path, used as given (relative to the
working directory), and must exist.

```
// toy build main.toy
extern "toyffi" {         // error: library 'toyffi' not found in /usr/local/lib,
    fn toyffi_add(a: int, b: int) -> int   // /usr/lib or the system library cache
}
```

The error lists every folder it searched. Its note names the file it looked for on the
target and the target's system library cache: on macOS `libtoyffi.dylib` and the dyld
shared cache, which holds the system libraries such as `libz` and `libsqlite3`. A name
written with its `lib` prefix shows up there doubled (`liblibtoyffi.dylib`). A `-l` flag that finds nothing is a usage error (exit 2)
naming the flag; a library named in source is reported at its block.

Fixes:

- Pass the folder that holds the library: `toy build main.toy -L path/to/lib`.
- Check the spelling: `extern "sqlite3"` looks for `libsqlite3`, without the `lib`
  prefix or the extension.
- Or name the file by path: `extern "./vendor/libfoo.dylib"`.
