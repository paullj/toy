# T0083: constant not known at compile time

A constant (`N :=: e` or `N: T =: e`) has no storage: every use of `N` is replaced by
its value, so the compiler must work that value out while it compiles. The initializer
may hold literals (int, float, bool, char, str), other constants, an enum's unit
variant (`Color.Red`, or `.Red` when the type is written; `Option[int].none` for a
generic enum), and the operators over them:
the integer, float, comparison and boolean operators. Anything else is rejected, as is
an expression that has no value, such as a division by zero, and a comparison whose order
comes from a user `Ord` impl. In a `when`, every arm must fold, whichever is taken,
so a build does not depend on the target; an arm the `when` does not take may still be a
`compile_error` or use a payload binding (`n` in `.B(n)`), which has a type but no
value, as no constant holds a payload. The initializer is typed first, as any expression is, so
its type errors are reported as they would be in a function body. A local
constant cannot take its type from its function's type parameter: the value would need
a different type in each instantiation.

```
fn ten() -> int { 10 }
struct Point { x: int, y: int }

N :=: ten()                 # error: a call runs only when the program runs
ORIGIN :=: Point { x: 0, y: 0 }  # error: a struct is built when the program runs
M :=: 1 / 0                 # error: a division by zero has no value
```

Fixes:

- Write the value out: `N :=: 10`.
- Use a variable inside a function when the value is only known at run time:
  `n := ten()`.
