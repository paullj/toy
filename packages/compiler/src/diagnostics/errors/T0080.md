# T0080: callback not capture-free

An `extern` parameter of a function type is a C function pointer. C calls it with its
own arguments and nothing else, so the function passed there cannot need an
environment. It must be one of:

- a top-level function named directly (`sort(p, n, 8, by_len)`, or `m.by_len`);
- an associated function named through its type (`Order.by_len`, `Box[int].make`);
- a lambda that captures nothing (`fn(a, b) { .. }` reading only its params);
- a local fn that captures nothing.

Anything else is rejected at the argument: a lambda or local fn that reads a local of
the function around it, a bound method (`acc.get`), or any other function value (a
local, a field, a call result), whose environment the compiler cannot prove empty.
Local fns that name each other share one environment, so a local fn that captures
nothing is rejected too when it shares one with a sibling that captures; a lambda that
calls a local fn captures that fn.

```
extern fn each(n: int, cb: fn(int) -> int) -> int

fn main() -> int {
    k := 3
    f := fn(x: int) -> int { x * 2 }
    a := unsafe { each(4, fn(x) { x + k }) }  // error: the lambda captures 'k'
    b := unsafe { each(4, f) }                // error: 'f' is a value, not a function name
    return a + b
}
```

Fixes:

- Pass what the callback needs through its own parameters. Most C APIs that take a
  callback also take a `void*` context they hand back to it; declare it as `rawptr`.
- Move the function to the top level and name it directly.
- Write the lambda in place instead of storing it in a local first.
